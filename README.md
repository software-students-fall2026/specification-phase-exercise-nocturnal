## Review of the Current Application

### Strength

1. The Slide Machine does well at pulling out the key information from lecturer's speech, discarding stutters and rambling.
2. The generated texts are better organized than the lecturer's own notes (seed material).
3. The generated slides are well formatted, without overcrowding and are visually pleasing for viewers.

### Weakness

4. The photos generated by the lecturer are relevant but not always accurate and may not reflect the intended meaning.
5. Some Exit Quiz questions only feature answer options that were never mentioned by the lecturer. This can confuse viewers, as they are being tested on information that wasn't taught.
6. Some Exit Quiz questions are drawn from a term the lecturer mentioned in passing. The question may not reflect the core concept the lecturer wants the viewer to take away from the lecture.
7. The slide generator sometimes splits a single idea across two slides, breaking up material that was intended to belong together.

### Gap

8. There is no way for the lecturer to hold the current slide in place while still speaking about it.
9. There is no live way for a viewer to follow a lecture on their own device as the slides are generated.
10. Lecturers are unable to edit the slides by voice after the lecture ends.

## Prior Art & Originality

We inspected “The Slide Machine” GitHub repository beginning with SPEC.md. Our focus was on goals and non-goals, live lecture capture, voice commands, slide generation, post-lecture refinement, editing, future work, and open questions. We also investigated ROADMAP.md, DECISIONS.md, and ACTIONS.md. Finally, we glanced over deck.ts, slide.ts, voice-commands.ts, and commands.ts as these code files are relevant to our proposal. 

Based on this review, our proposed "Mark for Review" workflow is not currently implemented, specified as future work, or recorded as a previously dismissed feature. Our plan extends Slide Machine's existing Refine process and voice-command system. Correction indicators in lecture, recording feedback without immediately changing the projected/current slide, carrying the feedback into Refine, and the associated "Live Correction Queue", review, and correction-history views would be new to the current Slide Machine repository.

## Product Vision Statement

During a live lecture, The Slide Machine will allow instructors to Mark for Review potentially incorrect AI-generated slides without interrupting presentation flow, then carry those issues into a post-lecture Review Queue for targeted correction, and ensure students can distinguish content that is still under review from the latest instructor-approved version.

## User Requirements

### Instructor

1. As an instructor, I want to Mark for Review the currently displayed slide with a button or keyboard shortcut so that I can indicate a problem without interrupting my lecture.
2. As an instructor, I want to Mark for Review a slide using a voice command so that I can report an issue without stopping to interact with the interface.
3. As an instructor, I want to briefly describe what is wrong when I Mark for Review a slide so that I remember what needs to be corrected after the lecture.
4. As an instructor, I want the current slide to remain displayed after I Mark it for Review so that reporting a problem does not disrupt my train of thought.
5. As an instructor, I want confirmation showing which slide was Marked for Review so that I know the correct issue was recorded.
6. As an instructor, I want to undo an accidental Mark for Review so that mistakenly selected slides do not remain in my Review Queue.
7. As an instructor, I want to see all unresolved slides that were Marked for Review in one queue so that I do not have to search through the entire presentation after class.
8. As an instructor, I want to open the affected slide directly from the Review Queue so that I can quickly investigate and correct the reported problem.
9. As an instructor, I want to edit or remove the note associated with a slide in the Review Queue so that the recorded issue accurately reflects what needs to be corrected.
10. As an instructor, I want to send a marked issue into the existing Refine process so that the Slide Machine can generate a targeted correction for the affected slide.
11. As an instructor, I want Refine to target the affected part of a slide, such as its text, image, or layout, so that unrelated content is preserved.
12. As an instructor, I want to preview and compare a proposed correction with the current slide before approving it so that I retain control over AI-generated changes.
13. As an instructor, I want to accept, reject, revise, or regenerate a proposed correction so that I can decide what becomes the final version of the slide.
14. As an instructor, I want each review item to show whether it is unresolved, proposed, resolved, or dismissed so that I can track the status of corrections.
15. As an instructor, I want to be notified if unresolved review items remain before I share or export the presentation so that questionable content is not distributed accidentally.

### Student / Viewer

1. As a student, I want to see when an instructor has Marked a slide for Review so that I know the information may not yet be reliable.
2. As a student, I want the Mark for Review indicator to be clear and easy to recognize so that I understand its meaning without interrupting the lecture.
3. As a student, I want to distinguish a slide that is still under review from one that has been corrected so that I know the current status of its content.
4. As a student, I want a slide that is Marked for Review to remain visible during the lecture rather than being immediately replaced so that I can continue following the instructor without a distracting interruption.
5. As a student, I want the instructor's private review notes to remain hidden so that internal correction details do not distract from the lecture.
6. As a student, I want unapproved AI-generated corrections to remain hidden so that I only rely on changes the instructor has reviewed.
7. As a student, I want to see the corrected version of a slide after the instructor approves it so that I can study from accurate material.
8. As a student, I want to know which part of a slide was corrected so that I can update my lecture notes when necessary.
9. As a student, I want to return to corrected slides when reviewing the lecture after class so that I can verify the material I recorded during class.
10. As a student, I want shared or exported presentations to contain the latest instructor-approved version of each slide and indicate any content that is still under review so that I know which material is appropriate to study.
